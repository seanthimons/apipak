The EPA [AMOS user guide](https://www.epa.gov/comptox-tools/analytical-methods-and-open-spectral-amos-database-user-guide) establishes that AMOS serves analytical methods, spectra, fact sheets, product declarations, and safety data sheets, and documents public search/list use. It gives no HTTP contract for any operation below. Scoped searches of the adjacent AMOS harmonizer and ComptoxR repositories found no AMOS service implementation or independently captured wire request. ComptoxR's generated wrappers are downstream consumers of the same invalid schema and are not source-contract evidence.

Swagger 2 permits `file` only for a `formData` parameter, not as a Schema Object property; its allowed Schema Object types are the JSON Schema primitive types ([Parameter Object](https://spec.openapis.org/oas/v2.0.html#parameter-object), [Schema Object](https://spec.openapis.org/oas/v2.0.html#schema-object)). The `dict` and `array of strings` values below are likewise not Swagger 2 type values. No operation declares `consumes`, so the snapshot does not select a request media type.

## Result

All nine AMOS schema defects remain unresolved. The source evidence proves the declarations are invalid; it does not prove a replacement wire shape. The five nested-file operations remain blocked from multipart work (#9), and the four query-shape operations remain blocked from query serialization work (#8). A corrected upstream schema or service-owned controller/client source is the minimum evidence needed to resolve any row.
